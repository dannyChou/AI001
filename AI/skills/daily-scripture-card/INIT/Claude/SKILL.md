專案根目錄固定在（下稱 `<ROOT>`，一律用絕對路徑，不依賴目前 cwd）：

該目錄下已有完整資源：


## 觸發情境

使用者要求「做今天的卡片」「做 X 月 X 日的卡片」「套上次的程式」，或貼出讀經進度表並要求做卡片時，一律依本檔流程處理。若使用者沒有提供當天的讀經進度表，且 `<ROOT>` 也沒有留存最新進度表，先向使用者索取。

## 標準工作流程（五步，中間不要停）

1. **定位經文**：從使用者提供的讀經進度表，找出目標日期對應的經文段落（書卷＋章＋節）。進度表每行格式類似 `8月20日 (四) 尼希米記 13 : 1 ~ 14`；找不到該日就先問使用者。
2. **核對經文原文**：用 WebSearch/WebFetch 查證當日經文的和合本繁體中文原句（尤其是要放進 `.verse` 區塊或引用的句子），避免憑記憶引用出現錯字或竄改原句。
3. **提煉主題＋撰寫 HTML**：讀懂經文核心，轉成非基督徒也能領受的生活化主題（見下「內容原則」）；`cp <ROOT>/assets/card_template.html <ROOT>/cards/card_YYYYMMDD.html`，替換日期、標題、副標、（經節區塊）、三段內文、引言、頁尾，並置換 SVG 插圖。
4. **產圖前檢查＋渲染**：先用 grep 掃內文確認全繁中，再用 `<ROOT>/scripts/render_card.py` 渲染成 PNG。
5. **驗證＋回報**：用 Read 工具直接看 PNG（可裁切放大插圖區）或用 `<ROOT>/scripts/verify_pixels.py` 統計驗證，確認插圖與版面正常；回報使用者。

## 內容原則

目標是讓**沒有信仰背景的人**也能被觸動，而不是被說教；內容完成後，須以「楊寧亞牧師的福音與生命建造視角」及「吳勇長老的聖經真理與牧養視角」進行模擬審查，確認兼具聖經忠實度、福音核心、牧養溫度與生活共鳴後再輸出。

1. **主題必須經過前置審查，且符合聖經整體核心價值與該卷書整卷原則**
   - 先確認所設定的主題是否符合前述「前置審查框架」的三層檢查，並將以下項目記錄在案，作為後續所有創作的「定海神針」：
      - 定題意圖（為什麼選擇這個主題）
      - 對應的聖經核心價值
      - 該卷書的整卷原則
      - 該卷書的整卷關懷範圍
      - 虛擬的「楊寧亞×吳勇對話」（兩位導師的福音與牧養視角提問與回應）
   - 確認主題對應至少一項聖經核心價值：神的愛、恩典、真理、悔改、饒恕、盼望、救贖、生命更新與愛人如己等
   - 確認主題落在該卷書的整卷關懷範圍內，而非跨界或衝突
   - 確認主題最終能指向福音核心與生命更新，而非單純道德勸說
   - 若主題與聖經整體核心價值衝突、過度簡化或產生錯誤神學方向，必須重新設定主題
   - 此「主題校正」最多重複 3 次；3 次後仍無法符合聖經整體核心價值與該卷書原則，則不得使用該主題繼續創作
2. **先讀懂經文核心**
   - 先確認經文原意、人物處境及生命核心，再轉化成現代人能理解的生命議題
   - 例：潔淨聖殿＝把喧鬧算計請出去、為心留安靜
3. **經過福音與牧養雙重審查**
   - 以楊寧亞牧師的福音、生命更新與實踐角度，以及吳勇長老的聖經真理、生命建造與牧養關懷角度檢視
   - 避免只剩道德勸說、宗教口號或脫離經文原意的解讀
4. **轉成生活化標題**
   - 使用白話、溫暖、非宗教術語的表達，讓沒有信仰背景的人也能理解並產生好奇
   - 例：「為心留一方安靜」「各修一段牆」
5. **從人人有共鳴的經驗切入**
   - 第一段幾乎不談信仰，先從工作、家庭、關係、壓力、孤單、失敗、等待等普遍的人性處境切入，再自然連結經文
6. **先讓人感受到被理解，再帶入信仰**
   - 避免一開始使用「神要你……」「你應該……」等說教式語言
   - 先理解人的處境，再溫柔引導讀者看見經文中的恩典、真理與盼望
7. **受難／沉重經文溫柔導向盼望**
   - 不刻意描寫血腥、身體傷痛或製造恐懼
   - 改從「有人默默承擔」「你並不孤單」「黑暗不是最後的結局」等角度切入
   - 承認痛苦，但不要讓痛苦成為最後一句話
8. **復活／歡慶段落語氣轉亮**
   - 文字應呈現希望、新開始、光明與重新出發的感受
   - 視覺上可搭配明亮版配色，讓內容從沉重自然轉向盼望
9. **認罪／省察類經文**
   - 務必寫成溫柔、建設性的生命反省，不強化負面自我苛責
   - 可明確加入「不必苛責自己」「承認不足，是重新開始的第一步」等具有恩典與盼望的表達
10. **不把信仰寫成道德命令**
    - 避免單純使用「你應該」「你必須」要求讀者改變
    - 應引導讀者思考「我可以重新開始什麼」「今天是否能往前走一步」，讓生命回應自然發生
11. **真理不稀釋、語言要生活化**
    - 不可為了討好非信徒而扭曲或淡化聖經核心
    - 應做到「經文不扭曲、真理不稀釋，但表達有溫度、語言貼近生活」
12. **結尾留下盼望與思考空間**
    - 不要用說教或強迫性的結論收尾
    - 而是留下溫暖的祝福、生命提醒或一個可以帶回生活中思考的問題
13. **最終自我審查**
    - 產出前依序確認：
      1. 主題是否經過前置審查 → 符合聖經整體核心價值 → 符合該卷書整卷原則
      2. 經文是否正確
      3. 福音是否清楚
      4. 牧養是否溫柔
      5. 非信徒是否看得懂
      6. 是否具有生活共鳴
      7. 是否留下盼望
    - 任何一項不合格，都必須先修改後再輸出
    - 若「主題」本身不符合聖經整體核心價值與該卷書原則，回到前置審查框架重新定題，最多重複 3 次
    - 確認合適後才進入正式創作


### 直白信仰表達原則（務必維持）

不要用「古老的智慧」這類迂迴說法，要**直白正直地讓人知道這出自聖經與基督教信仰，但不激進、不施壓**：

- 明說出處：「**聖經的○○記裡……**」，直接稱呼**耶穌**、**神**。
- **引用經文原句**（簡短、加引號），關鍵詞可用 `<strong>` 強調。
- 誠實呈現經文事實（含人的失敗），不美化、不迴避。
- **結尾用「邀請」而非「要求」**：以「若你好奇……，歡迎有一天翻開聖經裡的○○記……」收束，把決定權留給讀者。

## HTML 版型規格

以 `<ROOT>/assets/card_template.html` 為基底，只替換內容，**不要改動版型 CSS**。

- **書籤直式**：`.bookmark` 寬 640px、米白紙、圓角、1.6px 虛線內框。
- **字型**：`Noto Serif CJK TC`（襯線，內文）＋`Noto Sans CJK TC`（無襯線，日期／副標／頁尾）。
- **色票**：`--paper:#F7F3EA`、`--ink:#3E3A33`、`--ink-soft:#7A756B`、`--sage:#8FA382`、`--wheat:#E3C282`、`--barn:#9A6B52`。
- **內容結構（由上而下）**：`.art` SVG插圖 → `.date`（`2026 / 08 / 20`）→ `h1` 中文主標題 → `.subtitle` 英文副標（全大寫）→ `.verse`（選用）→ `p.body`×3 → `.quote` → `.footer`。

### 三段內文的固定節奏

- **第 1 段**：從普遍人性處境切入，先不談信仰。
- **第 2 段**：帶入聖經敘事「聖經的○○記裡……」，引用原句，直白而溫柔。
- **第 3 段**：拉回讀者的「今天」（用當天星期，如「週四的清晨」），給溫柔的具體行動，並以邀請收尾。

### 標題後經節區塊 `.verse`（選用）

當使用者要求「在標題後放入經文」時，於副標下方放一個淡米色圓角框，內含當日經文裡 **1–2 節**切合主題的經句 + 出處：

```html
<div class="verse">
  <div class="txt">「那日，眾人獻大祭而歡樂……<br>耶路撒冷中歡樂的聲音聽到遠處。」</div>
  <span class="ref">尼希米記 12 : 43</span>
</div>
```

放此區塊時 `.subtitle` 的 `margin-bottom` 用 **28px**；不放時改回 **40px** 並刪除區塊。經句務必全繁中、加引號、與查證過的原文一致。

### 頁尾 `.footer`

- `.en`：**當日經文出處**，格式 `NEHEMIAH 13 : 1 – 14`（書卷英文大寫、全形間距、破折號 `–`；跨章如 `NEHEMIAH 9 : 38 – 10 : 39`）。
- `.bless`：**以「願神祝福你：」開頭**，接八字左右對稱短句。

### 標題過長處理

- 9–10 字：`h1` `font-size:38px; letter-spacing:.08em`。
- 12 字：`font-size:34px; letter-spacing:.04em`（實測仍可單行）。

### 常見陷阱（務必避免）

- **內容區絕不用 Markdown 星號** `**text**`（會照字面顯示）；強調一律 `<strong>`。
- 內文、經節、祝福語**全繁體中文**，不可混入英文單字。
- SVG 屬性值若打錯（出現非法字元），Chromium 仍會渲染但該元素消失 → 產圖後務必驗證。
- **HTML 註解裡不要示範嵌套 `<!-- -->`**：外層註解的說明文字若包含另一組 `<!-- ... -->`，會在第一個 `-->` 處提前把外層註解關閉，導致後面文字（含 `<strong>` 標籤）變成真的顯示內容，洩漏到卡片外側。曾在 `card_template.html` 開頭發生過，已修正；新增註解時避免重蹈。

## 渲染與驗證

### 產圖前檢查（全繁中）

```bash
grep -oE 'class="(body|txt)">[^<]*' <ROOT>/cards/card_YYYYMMDD.html | grep -iE '[a-z]{2,}' | grep -vE 'body|txt|br' || echo "內文與經節無英文夾雜"
```

### 渲染

```bash
python <ROOT>/scripts/render_card.py <ROOT>/cards/card_YYYYMMDD.html <ROOT>/images/morning_card_YYYYMMDD.png
```

（Playwright + Chromium headless，viewport 900×1200、device_scale_factor=2，等 800ms，對 body 截圖，產出約 1800px 寬。此機器上 python 執行檔名為 `python`，非 `python3`；playwright 套件與 Chromium、Noto Serif/Sans TC 字型已於本機安裝過。）

### 驗證（務必自行確認圖可正常顯示）

**第一優先：直接看圖。** 用 Read 工具開啟 PNG，確認版面、文字、插圖正常；再用 Bash + PIL 裁切上方約 5–30%（水平 15%–85%）另存暫存檔並用 Read 放大檢視插圖細節，看完刪除暫存檔。

**備援：像素統計。**

```bash
python <ROOT>/scripts/verify_pixels.py <ROOT>/images/morning_card_YYYYMMDD.png
```

健康值參考：unique_colors 約 4,000 起（明亮版可破萬）、art_marks > 1000、body_text > 800、footer > 100。判定 OK 即完整，並在回報時據實說明是否改用像素統計覆核。

### 命名慣例

- HTML：`<ROOT>/cards/card_YYYYMMDD.html`
- PNG：`<ROOT>/images/morning_card_YYYYMMDD.png`

## 回報使用者時

產圖後給一段簡短說明，涵蓋：**經文對應**（哪段、核心信息、主題）、**（若有）經節區塊說明**、**信仰表達**（如何直白引用又不施壓）、**視覺設計**（主體圖像＋系列元素）、**驗證情況**（若用像素備援據實說明），並可預告隔天經文的可能主題方向。語氣自然、不冗長。
